# 사용자 외형 의도를 이미지 생성 입력으로 옮기는 AI 서비스

확인일: 2026-10-07 · 상태: 단일 처리 경로 구현 및 합성 계약·HTTP 검증. 실제 Gemini 의미 정확도와 GPU 결과 품질은 이번 변경의 검증 범위가 아니다.

## 문제: 사용자가 프롬프트 엔지니어가 되어야 하는가

캐릭터 설정 화면에서 머리·체형·의상을 설명한 사용자가 이미지 생성 때 같은 내용을 영어 프롬프트로 다시 작성하게 하고 싶지 않았다. 그렇다고 자유 설명을 그대로 이미지 모델에 넘기거나, AI에게 “더 예쁘게 만들어 달라”고 맡기면 사용자가 의도한 특징이 누락되거나 다른 장식으로 바뀔 수 있다.

목표는 **AI가 캐릭터를 대신 창작하는 것이 아니라, 사용자가 작성한 외형 의도를 생성 모델이 사용할 표현으로 옮기는 것**이다. 작가의 설정과 실제 GPU 실행 사이에 독립 AI Service를 두고, 현재는 Gemini API를 해석·영어 표현 작성의 제공자로 사용한다. 이미지 생성은 계속 Image Worker와 ComfyUI가 담당한다.

## 왜 사전 치환만으로 처리하지 않았나

서버에 등록된 선택값은 코드로 변환할 수 있다. 하지만 “겉은 검정이고 안쪽은 빨강인 어깨 길이 머리”나 “다른 부분은 유지하고 하의만 바꿔 달라”는 자유 입력에는 수식 관계·유지·교체·제외의 문맥이 있다. 모든 조합을 사전과 규칙으로 관리하는 대신 문맥 해석에 AI를 사용하고, 권한과 입력 검증·구도·실행 선택은 코드에 남겼다.

기존에는 외형을 정리한 후 모델용 표현으로 다시 작성하는 두 단계였다. 현재 등록된 초기 전신·참조 외형 변경에서는 두 역할을 **한 번의 처리**로 묶었다. 중간 재작성에서 뜻이 달라질 기회와 호출 단계를 줄이려는 선택이며, 실제 정확도나 지연이 개선됐다는 측정 결과는 아니다.

## 이벤트 순서 예시

다음은 실제 사용자 자료가 아닌 설명·테스트용 합성 입력이다.

> 어깨까지 오는 단발. 머리 겉은 검정, 안쪽은 빨강. 흰 셔츠와 남색 무릎길이 주름치마. 안대는 제외.

| 순서 | 주체                 | 처리와 다음 단계                                                                                                                   |
| ---- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 사용자·Web           | 캐릭터 외형을 저장하고 생성할 모습을 요청한다. 영어 프롬프트를 다시 작성하지 않는다.                                               |
| 2    | Core API             | 사용자 권한과 선택한 외형 원본을 확인한다. 같은 입력으로 준비된 결과가 있으면 재사용한다.                                          |
| 3    | AI Service·Gemini    | 등록된 이미지 모델용 지침 아래 외형·추가 지시를 한 번에 해석한다. 영어 특징과 각 특징의 원문 근거·포함/제외를 반환하도록 요청한다. |
| 4    | AI Service·Core API  | 응답 형식, 출처, 의상 구성 누락과 제외 규칙 등을 검사한다. 사용자 입력이 처리 중 바뀌었는지도 다시 확인한다.                       |
| 5    | Core API             | 검증한 외형 표현에 대상별 구도와 서버 규칙을 조합한다. 원래 설정과 실행 입력을 고정해 이미지 작업을 등록한다.                      |
| 6    | Image Worker·ComfyUI | Worker가 등록된 작업을 조회해 실행한다. Gemini로 다시 번역하거나 브라우저에서 직접 GPU를 호출하지 않는다.                          |
| 7    | 사용자               | 비공개 후보를 확인한다. 생성 완료와 설정 준수·품질 승인은 별도로 판단한다.                                                         |

예를 들어 머리는 `black outer hair with red inner layers, shoulder-length bob`, 하의는 `navy knee-length pleated skirt`처럼 세부 관계를 남기도록 요구한다. 안대는 포함 특징이 아니라 제외 특징으로 처리한다. 이 영문은 의도를 설명하는 합성 예시이며 이번 Gemini 실응답을 인용한 것이 아니다.

외형 준비가 생성 버튼을 누르기 전에 수행될 수도 있다. 같은 설정이라면 생성 요청에서 그 결과를 사용하며 AI를 두 번 부르는 구조가 아니다. 추가 지시가 달라졌다면 달라진 전체 입력으로 다시 준비한다.

## AI와 코드가 각각 맡는 일

| AI에 맡긴 부분                  | 코드에 남긴 부분                            |
| ------------------------------- | ------------------------------------------- |
| 자유로운 외형 설명의 문맥 해석  | 권한·소유권과 사용량 제한                   |
| 근거를 붙인 영어 시각 특징 작성 | 응답 형식·출처·구성 누락 검사               |
| 등록된 모델 프로필에 맞춘 표현  | 모델·워크플로 선택, 구도와 조건부 기본값    |
| 명시된 유지·변경·제외의 표현    | 원문 보존·동시 변경 검사·작업 상태와 재사용 |

목적 지침은 버전 관리되는 Markdown으로 분리했다. 사용자 설명을 시스템 지시와 섞지 않고, 없는 의상·장식·체형을 임의로 채우지 않도록 한다. 다른 모습으로 편집할 때는 바꾸려는 부분만 처리해 기본 복장을 다시 넣지 않는다.

제공자 연결도 어댑터로 분리했다. 현재 구현은 Gemini이며 다른 제공자가 이미 지원된다는 뜻은 아니다. 새 제공자는 같은 계약과 실패 검증을 구현해야 한다. Web·Worker에 외부 모델 키를 전달하지 않는 서비스 경계는 유지한다.

## 재사용과 실패를 다루는 방법

- 같은 외형·추가 지시·등록 모델 조건에서 시드만 바꾸면 저장 결과를 사용한다. Worker 재시도에도 번역을 반복하지 않는다.
- 지원되는 순수 등록 선택값은 결정적 변환으로 외부 호출을 생략한다. 모든 자유 입력이 이 경로에 해당하지는 않는다.
- 정책이나 모델 조건이 달라지면 이전 결과와 구분해 준비한다. 제공자 설정 변경에는 운영자가 관리하는 재사용 기준 갱신도 필요하다.
- AI 처리나 검증이 실패하면 새 이미지 작업을 등록하지 않는다. 원문을 남기고 명시적인 재시도를 안내하며, 조용히 원문 실행으로 우회하지 않는다.
- 기존 작업과 승인 이미지는 재작성하지 않는다.

## 검증한 것과 아직 확인할 것

합성 제공자와 임시 PostgreSQL 호환 DB를 이용한 실제 Core HTTP 흐름에서 준비→생성 재사용, 시드 변경, 추가 지시 분리, 실패 시 미등록, 사용자 격리와 동시 처리 복구를 검사했다. AI 측 모의 HTTP에서는 제공자 전송 한 번, 잘못된 응답 거절, 새·기존 경로의 공유 실행 상한과 오류 본문 비노출을 확인했다.

이는 외부 API를 실제 호출한 품질 평가가 아니다. **원문 근거가 존재한다고 번역이 정확하다고 증명되지는 않는다.** 형식을 통과해도 “무릎길이”가 잘못 해석되거나 이미지 모델이 치마 형태를 다르게 그릴 수 있다. 다음 품질 검증은 동일한 합성 입력에서 원문, 영어 특징, 최종 이미지를 함께 비교하는 것이다.

호출 단계 감소와 캐시 재사용은 검증했지만 실제 토큰·비용 절감률, 평균 지연, 캐릭터 동일성 보장, 실기기 왕복 성공률은 주장하지 않는다. 이번 사례에는 실제 사용자 자료·원문 로그·내부 설정·생성 이미지 자산을 포함하지 않았다.
